# 카더라 말고 — 기획서

> **맘카페·블로그·유튜브 카더라 말고, 실제 연구 논문으로 확인하는 건강·육아 팩트체커**
>
> AGENTIC PLAYER 10 (카카오 PlayMCP 공모전 2회) 출품용 MCP 서버 기획서

---

## 1. 한 줄 컨셉

사용자가 어떤 주제든 "이거 진짜 맞아?"라고 물으면,
**실제 연구 논문을 근거로 인용하면서** "○○년 연구에 따르면 이렇고, 이런 방법이 효과 있더라"고
**한국어로 풀어서, 출처와 함께** 답해주는 MCP 서버.

검색 도구가 아니라 **"카더라 검증기"**. 정보를 던져주는 게 아니라 **근거를 대준다.**

**전 국민 대상**이며, 사용자가 **카테고리(건강/교육/육아/운동/영양/심리 등)를 선택**해
관심 분야에 맞춰 검증받을 수 있다.

---

## 2. 타깃과 문제 (왜 이걸 만드는가)

### 타깃 = 전 국민
- 특정 집단으로 좁히지 않는다. "카더라"에 노출되는 **모든 사람**이 타깃.
- 대신 **카테고리로 갈래를 나눠** 각자 관심 분야에서 쓸 수 있게 한다.
- 타깃이 넓을수록 본선 사용자 투표에 유리하다.

### 카테고리 구조
사용자가 분야를 선택하거나, 질문 내용으로 자동 분류된다. (예시)

| 카테고리 | 검증 대상 "카더라" 예시 |
|---|---|
| **건강** | "공복 유산소가 살 더 빠져?", "이 영양제 같이 먹어도 돼?" |
| **육아** | "우리 애 고기 안 먹는데 괜찮아?", "영상 보여줘도 돼?" |
| **교육** | "어릴 때 외국어 노출이 효과 있어?", "이 학습법 진짜야?" |
| **운동** | "단백질 하루 얼마나?", "스트레칭 부상 예방돼?" |
| **영양/식단** | "간헐적 단식 효과 있어?", "탄수 끊으면 위험해?" |
| **심리/수면** | "수면 부족이 집중력에 영향?", "이 습관이 불안에 도움?" |
| (확장) | 분야는 점진적으로 추가 가능 (엔진 동일) |

- 카테고리는 **검색 키워드 변환과 데이터 소스 우선순위를 최적화**하는 데도 쓰인다.
  (예: 건강·육아 → PubMed/Cochrane 우선, 교육 → ERIC·심리/교육 논문 우선)

### 핵심 고통 (분야 공통)
- 정보를 검색하면 → **카페 카더라, 블로그 광고, 출처 불명 유튜브**가 쏟아짐
- "이게 맞는 말이야?"라는 **불안**이 해소되지 않음
- 논문을 직접 찾자니 영어이고, 어렵고, 시간이 없음

### 우리가 주는 가치 = **신뢰**
- "카더라"가 아니라 **"실제 연구가 이렇게 말한다 + 출처는 여기"**
- 영어 논문을 **일반인 눈높이의 한국어**로 풀이
- 근거의 **등급**(메타분석 > 임상연구 > 단일연구)까지 구분해 제시

## 3. 왜 이 아이디어가 강한가 (수상 전략)

### 3-1. 수상작 분석에서 도출한 공식

1회 공모전(MCP Player 10) 수상작 분석 결과, 수상 공식은:

> **"특정 집단의 + 반복되는 + 진짜 고통을 + 끝까지 해결"** + (2회는) **대중 투표 대응**

- **1등 어린이ZIP**: 교사의 행정 야근 → "기술로 퇴근을 앞당기자" + 유료 구독까지
- **2등 SeedUp**: 창업가의 "지루하지만 고통스러운" 정부 공고 서칭 해결

### 3-2. '카더라 말고'의 기준 충족도

| 기준 | 충족 | 비고 |
|---|---|---|
| MCP 본질 (외부 API를 AI로 호출) | ✅ | 논문 API 호출이 핵심 |
| GPT로 못 함 | ✅✅ | GPT는 카더라/환각. 이건 실제 논문 인용 |
| 데이터 합법성 | ✅ | PubMed·Semantic Scholar 등 전부 무료 공식 API |
| 타깃 절박함 | ✅✅ | "이거 진짜야?"는 분야 불문 모두의 불안 |
| 대중성 (본선 투표) | ✅✅ | 전 국민 대상 + 카테고리로 전 분야 커버 |
| 차별화 | ✅ | "근거 있는 답"이라는 신뢰. 검색기와 다름 |
| 제작자 강점 | ✅ | 데이터 정제 + RAG 경험과 직결 |

### 3-3. 핵심 차별점 — "검색"이 아니라 "검증·해석"

- 기존 논문 MCP(paper-search, AIRA 등)는 전부 **연구자용 "검색 도구"** → 영어 논문 목록을 던져줌
- '카더라 말고'는 **일반인용 "검증·해석 도구"** → 질문을 연구 키워드로 바꾸고, 실제 논문을 찾아, 한국어로 결론과 근거를 조립
- → 같은 데이터(PubMed)를 써도 **완전히 다른 물건** (택배 API는 흔해도 "스미싱 필터"로 차별화한 택배추적기와 동일 전략)

### 3-4. 2회 공모전 특성 대응
- **예선**: 카카오 내부 심사 (창의성·편의성·안정성) → 완성도·신뢰성으로 통과
- **본선**: 내부 심사 + **Kakao Tools 사용자 투표** (8/31~9/28) → 대중성으로 공략
- '카더라 말고'는 **대중 투표용**으로 설계 (vs 이미지→엑셀은 실무·심사용)

## 4. 데이터 소스 (API 리스트)

> 모두 **무료**. 대부분 영어 → 한국어 변환이 핵심 작업이자 차별점.

### 1순위 — 연구·논문 본체 (답변의 핵심 재료)

| API | 제공 내용 | 비용/제한 |
|---|---|---|
| **PubMed (E-utilities)** | 의학·영양·운동·발달 연구 본진 | 무료. 키 없이 3req/s, 키 발급 시 10req/s |
| **Semantic Scholar (Graph API)** | 2억+ 논문, AI 요약·인용수, 분야 넓음 | 무료(키 발급 시 안정적) |
| **OpenAlex** | 커버리지 최고(98%), JSON 깔끔 | 무료, 인증 불필요 |
| **Europe PMC** | PubMed 유럽판, full-text 접근 넓음 | 무료 |
| **CORE** | 전 세계 오픈액세스 풀텍스트 | 무료(키 발급) |

### 2순위 — 권위·신뢰 보강

| API | 제공 내용 | 비고 |
|---|---|---|
| **Cochrane Library** | **메타분석 (최상위 근거)** | ⭐ 꼭 활용. 신뢰도 격상 |
| **WHO GHO (OData)** | 세계보건기구 공식 보건 지표·통계 | 무료, 인증 불필요 |
| **CDC** | 질병·예방·백신 공식 데이터 | 무료 |
| **MyHealthfinder (ODPHP)** | 일반인용 쉬운 언어 건강 권고 | 무료. 번역 부담 적음 |

### 3순위 — 분야 확장·최신성

| API | 제공 내용 | 주의 |
|---|---|---|
| **arXiv** | 운동과학·영양·AI·기술 프리프린트 | 무료, 키 불필요 |
| **bioRxiv / medRxiv** | 최신 의학·생물 프리프린트 | 정식 게재 전 → 신뢰도 한 단계 낮음, 표기 필요 |
| **Crossref** | DOI·서지정보 메타데이터 | 출처 정확 표기용. 무료 |

### 카테고리별 전문 소스 (해당 분야 질문 시 우선 사용)

| 카테고리 | 전용/우선 소스 |
|---|---|
| 건강·육아·영양·운동 | PubMed, Cochrane, Europe PMC |
| **교육·학습** | **ERIC** (미 교육부 교육학 논문 DB, 무료 API), Semantic Scholar |
| 심리 | PubMed(정신의학), Semantic Scholar, PsyArXiv |
| 전 분야 공통 보강 | OpenAlex, Semantic Scholar (분야 무관 커버) |

### 한국 보강 (선택)

| API | 제공 내용 |
|---|---|
| **KCI (한국학술지인용색인)** | 한국 논문 (한국인 대상 연구·한국 식습관 등) |
| **RISS** | 학술연구정보·학위논문 |

### 실전 추천 구성 (MVP)
- **핵심 4**: PubMed + Semantic Scholar + OpenAlex + Cochrane
- **권위 보강 2**: WHO + MyHealthfinder
- **출처 보조 1**: Crossref
- 한국 논문(KCI)은 한국 특화 질문 늘면 추가

## 5. 핵심 동작 흐름

### 5-1. 답변 생성 파이프라인

```
[사용자 질문]
  "우리 애 고기를 잘 안 먹는데 괜찮을까?"
        │
        ▼
[0. 카테고리 분류]
  선택했거나 자동 분류 → "육아" → 데이터 소스 우선순위 결정
  (육아 → PubMed/Cochrane 우선, 교육이면 ERIC 우선 등)
        │
        ▼
[1. DB(캐시) 확인]
  이 주제 이미 검색·저장돼 있나?
        │
   ┌────┴────┐
   있음        없음
   │            │
   ▼            ▼
[즉답]      [2. 키워드 변환]
(빠름)      "child meat aversion / picky eating / iron protein intake"
            │
            ▼
        [3. 논문 API 검색]
        (카테고리 우선순위에 따라) PubMed → Semantic Scholar → OpenAlex → Cochrane
            │
            ▼
        [4. 근거 등급 정렬]
        Cochrane 메타분석 > 임상연구 > 단일연구 > 프리프린트
            │
            ▼
        [5. 한국어 변환 + 답변 조립]
        "여러 연구에 따르면 영유아 편식은 흔하며,
         ○○ 연구(2024)에서는 △△로 봅니다.
         다만 □□ 신호가 있으면 전문가 상담을 권합니다."
         + [출처: 논문 제목·연도·링크]
            │
            ▼
        [6. DB에 저장 + (카테고리·주제) 카운트 +1]
        (다음 사람부터는 즉답, 인기 주제 자동 축적)
```

### 5-2. 캐싱 + RAG 구조 (제작자 강점 영역)
- **시작은 가볍게**: DB 미리 안 채워도 됨. 실시간 검색으로 출발.
- **쓸수록 빨라지고 똑똑해짐**: 한번 검색한 주제는 저장 → 재사용. 호출·번역 비용 절약.
- **자주 묻는 주제 자동 축적**: 미리 예측 불필요. 사용자 질문 빈도가 곧 DB 우선순위.
- **최신성 관리**: 저장 데이터에 유효기간(예: 30일) → 오래되면 재검색해 갱신.

### 5-3. 2단계 저장 구조 — "무지성 저장 ❌, 검증된 것만 정제 저장 ✅"

핵심 원칙: **풀가공(번역+다계층 분류)은 2회 이상 질문된 주제에만.**
(1회짜리까지 다 정제하면 안 물어볼 주제까지 비용 낭비)

```
[1회차 질문]
  → 실시간 검색 → 답변
  → 임시 캐시에 가볍게 저장 + 카운트 = 1

[2회차 이상 — 정식 DB로 승격]
  → 번역: 한글 요약 (원문·출처 링크 반드시 함께 보관)
  → 카테고리 분류: 다계층 (아래 5-4)
  → 다중 카테고리 태그 허용 (한 논문이 여러 분야 걸치면 여러 태그)
  → 벡터 임베딩 함께 저장 (의미 기반 검색용)
  → 유효기간 표시 (최신성 관리)
```

### 5-4. 다계층 카테고리 분류 (3차~5차)

- **1~2차 = 고정 골격** (건강 / 교육 / 육아 / 운동 / 영양 / 심리 …)
- **3~5차 = AI 가변 깊이** (주제마다 자연스러운 깊이가 다름 → AI가 판단해 세분화)
- 예시:
  ```
  건강 > 영양 > 단백질 > 섭취량 > 운동 후 타이밍   (5차)
  교육 > 언어 > 외국어 > 조기노출 효과            (4차)
  육아 > 식습관 > 편식                            (3차)
  ```
- **다중 분류 허용**: "운동이 아이 집중력에 미치는 영향" 논문 → [육아 + 운동 + 교육] 동시 태그

### 5-5. 검색은 "분류 + 임베딩" 병행

분류의 목적은 **나중에 정확히 찾기**. 구조적 분류만으론 "단어는 다른데 뜻이 같은" 질문을 놓침.
- **카테고리 분류** → 1차로 범위 좁힘 (구조적)
- **벡터 임베딩** → 의미가 비슷한 것 찾기 (의미적)
- 둘 다 저장해 검색 정확도 극대화 (제작자의 SLM·RAG 경험 활용 영역)

### 5-6. 응답(출력) 형식 — ⏳ 추후 결정

> 응답 형식(답변 문장 구조, 출처 표기 방식, 길이 등)은 **MVP를 먼저 만들어
> 실제 답변을 뽑아본 뒤** 결정한다. 미리 확정하지 않음.
> (방향성만: 결론 → 근거(연구 인용) → 출처 → 전문가 상담 권유)

## 6. 차별화의 핵심 — 근거 등급 로직

단순히 논문을 던지는 게 아니라 **근거의 강도를 구분**해 제시한다. 이게 검색기와의 결정적 차이.

```
1) Cochrane 메타분석 존재 → 최우선 ("여러 연구를 종합하면…", 강한 근거)
2) 없으면 → PubMed/Semantic Scholar 임상연구 ("한 임상연구에서는…")
3) 보조 → OpenAlex/Europe PMC로 보강
4) 공식 권고 → WHO/MyHealthfinder 덧붙임 ("WHO도 이렇게 권고함")
5) 출처 → Crossref로 정확히 표기 (제목·저자·연도·DOI·링크)
```

- "메타분석에 따르면(강함)" vs "한 연구에서는(약함)"을 구분 → 신뢰감 + 정직함

## 7. 안전장치 (생명선)

### 7-1. 환각(거짓 인용) 차단 — 최우선
- **반드시 API로 실제 검색된 논문만 인용.** AI가 없는 연구를 지어내면 안 됨.
- 모든 인용에 **원문 출처·링크**를 함께 제공 (한글은 이해용, 원문·링크는 신뢰용)
- 검색 결과가 없으면 → "관련된 신뢰할 만한 연구를 찾지 못했습니다"라고 정직하게 답 (지어내지 않음)

### 7-2. 의료 조언 경계 — 법적·윤리적 선
- **진단·처방은 절대 하지 않음.** "연구 결과 전달 + 전문가 상담 권유"로 포지셔닝.
- 답변 말미에 일관되게: "이는 연구 정보 제공이며, 우려가 있으면 의사·전문가와 상담하세요."
- 응급·중증 의심 질문은 즉시 전문기관 안내로 전환.

### 7-3. 개인정보 — 카카오 심사 통과 필수 요건
- 건강·육아 질문은 **민감정보**. 개인 식별·프로파일링 금지.
- **"누가 물었는지"는 버리고, "무엇을 물었는지의 익명 집계"만 보관.**
- 개인별 질문 이력 추적 안 함. 이용약관·개인정보처리방침에 명시.

## 8. 사업성·확장 그림 (심사 어필용)

> 1등 어린이ZIP이 결제·요금제까지 붙여 "사업"을 증명한 것처럼, 확장 그림을 제시.

- **기본**: 무료 카더라 검증 Q&A
- **확장 1 — 데이터 자산화**: 사용자 질문의 **익명 집계 트렌드**가 곧 "국민 관심사 데이터".
  - **카테고리별** "이번 달 가장 많이 검증된 카더라 TOP 20" (건강/교육/육아…) → 재방문·바이럴 유도 (본선 투표 유리)
  - 분야별 트렌드 리포트, 다음 서비스 기획의 1차 시장조사 데이터
  - ※ 반드시 **익명·집계**로만. 개인 정보 수집·판매 금지.
- **확장 2 — 카테고리 확대**: 초기 분야(건강·육아·교육·운동·영양·심리) → 점진적으로 분야 추가 (엔진 동일)
- **확장 3 — 프리미엄**: 심층 리포트, 특정 주제 정기 브리핑 등 유료화 여지

## 9. 제작 우선순위 (MVP → 확장)

### MVP (예선 통과 목표)
1. PubMed + Semantic Scholar 연동 (핵심 2개)
2. 질문 → 카테고리 분류 → 키워드 변환 → 검색 → 한국어 답변 + 출처
3. 환각 차단 (실제 검색된 것만 인용)
4. 의료 경계 문구
5. 2단계 저장: 1회차 임시캐시 → 2회차+ 정식 정제 저장
6. 카테고리 2~3개로 시작 (건강·육아·교육 등), 1~2차 고정 골격
7. ⏳ 응답 형식은 실제 답변 뽑아보고 결정

### 확장 (본선·고도화)
8. Cochrane(메타분석) + 근거 등급 로직
9. 다계층 분류(3~5차) + 다중 태그 + 벡터 임베딩 검색
10. OpenAlex·Europe PMC·WHO·MyHealthfinder·ERIC 추가
11. 카테고리 확대 + 카테고리별 "인기 카더라 TOP" 기능
12. 최신성 관리(캐시 유효기간)
13. 한국 논문(KCI) 보강

## 부록 — 핵심 의사결정 요약 (왜 이렇게 정했나)

- **왜 검색기가 아니라 검증기인가?** 논문 검색 MCP는 이미 흔함(레드오션). "일반인 대상 카더라 검증"은 빈 포지셔닝.
- **왜 WHO/CDC가 메인이 아닌가?** 그것들은 "국가 통계 지표"라 개인 건강 질문엔 안 맞음. 개인 질문엔 PubMed 등 "연구"가 답. WHO/CDC는 권위 보강용.
- **왜 캐싱+RAG인가?** 자주 묻는 걸 미리 예측 불가 → 사용자 질문이 쌓이며 자동으로 인기 주제 DB 구축. 쓸수록 강해지는 구조.
- **왜 익명 집계만?** 건강은 민감정보 → 개인 수집은 법 위반·심사 탈락. 익명 집계 트렌드만으로도 충분히 가치.
- **본 프로젝트의 역할 분담**: 이미지→엑셀(실무·예선용) + 카더라 말고(대중·투표용) = 인당 2개 출품의 상호 보완 구성.
